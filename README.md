# 健康温州 · 个人医疗健康数据分析服务

> 依托「温州医疗数据高铁」与 AI 大模型（GLM），为患者提供**全科视角**的智能健康解读服务。
> 患者端部署于「健康温州」小程序，医生端为「HI 医生」（AI 云医院医护端），实现 **AI 初解读 + 医生把关 + 医生受益** 的完整闭环。

线上体验：
- 患者端（健康温州小程序）：https://wenzhou-health-ai-analysis-production.up.railway.app/
- HI 医生端：https://wenzhou-health-ai-analysis-production.up.railway.app/doctor
- 源码仓库：https://github.com/salusmedia/wenzhou-health-ai-analysis

## 一、服务概述

本服务是一款面向个人的、以 AI 大模型为核心的智能健康数据解读服务。它不替代医生诊断，而是把散落在全市各机构的医疗数据，转化为患者听得懂、用得上的健康认知。

- **数据底座**：温州医疗数据高铁（全市医疗机构就诊/检验/影像/用药数据，演示环境内置模拟数据）
- **服务性质**：面向个人的付费增值服务
- **AI 引擎**：GLM 大模型（智谱 AI），未配置密钥时自动降级为内置结构化引擎，功能可完整体验

## 二、已实现功能（对应方案）

### 患者端 · 健康温州小程序
| 模块 | 功能 |
|------|------|
| 智能健康档案 | 多机构数据聚合、慢病专区、就医时间轴、检验/影像/用药一览、关键指标趋势图 |
| AI 健康助理 | 对话式解读，读取真实档案作答，**标注数据来源**、内置安全提示与高风险护栏 |
| 个人健康报告 | AI 综述 + 综合评分 + 关键指标趋势 + 就诊摘要 + 用药管控 + 分级随诊建议 |
| 诊前准备助手 ★ | 一键生成「就诊摘要（一页纸病情速览）+ 智能提问清单」，带入诊室 |
| AI 第二意见 ★ | 基于完整数据的独立分析：横向印证、查漏补缺、辅助决策 |
| 慢病长期管理 | 关键指标趋势追踪、用药执行、随访建议 |
| 数据授权管理 | **分类型授权开关**、授权记录留存可追溯、一键撤回，我的数据我做主 |
| 一键连通医生 | 把 AI 分析结果同屏推送给签约/主治医生 |
| 服务与会员 | 定价方案（示意）、订单、医生分成展示 |

### 医生端 · HI 医生（AI 云医院医护端）
| 模块 | 功能 |
|------|------|
| 工作台 | 待接诊、患者数、累计解读、解读分成收入总览 + 服务闭环说明 |
| 接诊 / 医患同屏 | 查看与患者**完全一致**的 AI 分析结果（医患同屏），患者病史/用药/异常检验一览 |
| 解读把关 | 医生提交专业解读与建议，回传患者 |
| 费用分成 | 解读完成自动结算分成，收入明细透明可查 |

### 数据安全与合规
- 分类型授权、最小必要调用、授权/数据调用全程留痕可审计
- 医学免责与安全边界声明；高风险问题（自行调整用药、急症）主动拦截并引导就医
- 每条 AI 结论标注数据来源，附「仅供参考、请遵医嘱」

## 三、技术架构

```
患者端(健康温州) / HI 医生端  ——  静态 SPA（原生 JS，移动端优化）
                │  REST API (JWT 鉴权)
        Express 应用层
                │
      AI 分析层（上下文构建 + GLM 调用 + 安全护栏 + 降级引擎）
                │
      数据层（sql.js / SQLite，纯 JS 无原生依赖）
```

- **后端**：Node.js + Express
- **数据库**：sql.js（WebAssembly SQLite，零原生编译，Railway 部署无依赖问题）
- **AI**：GLM（智谱 AI）Chat Completions，OpenAI 兼容格式

## 四、本地运行

```bash
npm install
cp .env.example .env      # 填入 GLM_API_KEY（可选）
npm start                 # 默认 http://localhost:3000
```

## 五、环境变量

| 变量 | 说明 |
|------|------|
| `PORT` | 服务端口，默认 3000 |
| `JWT_SECRET` | JWT 签名密钥（生产请修改） |
| `GLM_API_KEY` | 智谱 GLM API Key（申请：https://open.bigmodel.cn/），留空则用内置演示引擎 |
| `GLM_BASE_URL` | GLM 端点，默认 `https://open.bigmodel.cn/api/paas/v4` |
| `GLM_MODEL` | 模型名（如 GLM-5.2 / glm-4.5 / glm-4-plus），默认 `glm-4.5` |
